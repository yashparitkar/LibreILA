This covers `drivers/python/session.py`, the layer both front ends drive. It holds one connection to one core and every operation that can be asked of it, so that `libre_ila.py` and the GUI differ in **lifetime and nothing else**: the command line builds a session, runs its verbs and drops it, while the GUI keeps one alive per tab.

That difference is why this test exists separately from [02_cli](../02_cli/README.md). 02_cli already reaches the session through argparse, but only ever with the command line's lifetime — one connection, one invocation, then exit. What it cannot reach is the other lifetime, and the properties that only show up there.

`TestOnePortManyOperations` is the point of the whole layer. `Port` counts how many times a session opened one, because "do not reopen the port per action" is a claim that can only be checked by counting: a whole capture — trigger write, position, read back, status, info, arm, readout — has to come to **one** open and **one** read of the identity block. Reopening per action would pay for that block every time and, worse, could not hold the port across two actions at all, since [driver.py](../../../drivers/python/driver.py) flushes the input buffer on every transaction and the wrapper is a request/response protocol over a single port. A status poll is pinned at exactly one packet for the same reason: a front end polls it on a timer to keep a state display honest, so what it costs is part of the interface.

Worth knowing about the rest:

* **A session is built disconnected.** That is what lets a view exist for a device that is not answering yet, which is what a tab titled DISCONNECTED is. Every operation before `connect()` is refused with `REASON_USAGE` and the port named, rather than a port being opened behind the caller's back.
* **`disconnect()` writes nothing.** `TestLifetime` compares the packet log across it. A capture left armed has to survive the host letting go of it, which is the whole reason the core is the record and the host keeps no state worth saving.
* **A port answering as another core is refused.** Ports get renumbered between boots and UIDs do not, so a session built from the device store checks what answered and closes the port again if it is the wrong one.
* **`armed_for()` is the one piece of host side state.** The core reports that it is armed, not how long it has been. So a fresh session attached to an already-armed core returns `None` rather than a number, because a wrong elapsed time on a display is worse than none.
* **Reasons, not messages, are what the tests pin.** A message is for a human and a reason is for the code: `libre_ila.py` maps reasons onto exit statuses and a GUI maps them onto whatever it shows. `test_every_reason_the_session_defines_is_raised_somewhere` catches a reason nothing raises, which is a case a front end has to handle that cannot happen.
* **`test_a_refusal_mid_session_never_names_a_flag`** is the layering invariant. The answer to a capture that has not finished is `--wait-done` on the command line and a button in a window, so the session states the fact and stops. The flags live in `libre_ila._libre_ila_reason_hint`, keyed by reason.
* **The progress callback ends exactly at the word count.** The readout is the one operation that takes seconds rather than a packet, and a progress bar that never fills is worse than none.

The device store is here rather than in the CLI because both front ends read it: a core added with `--add-device` should come up as a tab, and one added in a tab should be reachable with `--device`. That only holds while there is one store, so `TestDeviceStore` covers the directory being overridable, the default directory dropping out of the path entirely (the name goes into messages the user reads), and the glob still refusing to delete a file that merely starts with the prefix.

Like 02_cli, this imports `FakeWrapper` from [00_pkt_format](../00_pkt_format/README.md) rather than copying it, so the two cannot drift, and loading that module is also what installs the pyserial stub that keeps this test off any real `/dev` node.
