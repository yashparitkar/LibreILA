This drives `drivers/python/libre_ila.py` end to end — every verb, against the same `FakeWrapper` model of the UART wrapper that [00_pkt_format](../00_pkt_format/README.md) checks the packet format with. It imports that model rather than copying it, so the two cannot drift.

The CLI is worth testing at this level because almost nothing it does is visible from the driver's own tests. It decides *when* to open a port, what to do with a stored device file, how to merge a half-given trigger setup into the one the core already holds, and what exit status to hand back. All of that sits between argparse and `driver.py`, and none of it is reachable from either.

Three of the cases exist because the earlier sketch of this file got them wrong, and each failure was silent rather than loud:

* **Exit statuses are POSIX process statuses.** The sketch used `-1` and `-2`, which reach a shell as 255 and 254 — the range that means "killed by a signal". `test_every_status_survives_a_process_exit` runs each one through a real interpreter and checks what the shell actually sees.
* **`--reset` deletes files.** It takes no argument and matches a pattern, so `test_reset_leaves_everything_else_alone` stages neighbours (`notes.txt`, `libreila_device.txt`, `libreila_deviceX.txt`) and checks they survive. The sketch shelled out with `exec("rm libreila_device*")`, which is not shell and not even valid Python.
* **A trigger value above the probe width breaks the trigger rather than being ignored.** The core zero-extends each sample to the full register stride before comparing ([libre_ila.vhdl](../../../hdl/libre_ila.vhdl) `trig_samp_word <= resize(...)`), so a mask bit up in the padding fires an `or` trigger on the first sample and stops an `and` trigger from ever firing. `TestTriggerRange` pins the rejection.

`TestTriggerMerge` covers the other thing the CLI owns: `configure_trigger` writes the condition, the mask and the mode as one unit, so setting only one of them has to read the other two back out of the core first. The register block is readable back precisely so this works, and it is what lets one invocation arm a capture and a later one adjust a single field without disturbing the rest.
